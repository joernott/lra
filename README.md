# lra - a lowlevel REST api client

This package handles REST API calls and allows for using http and socks proxies
as well as self signed certificates. It also allows the specification of
headers to be sent with every request.

I wrote this after copying code for various tools connecting to different REST
APIs. It consolidates the low level functionality of establishing/configuring
a connection and doing the HTTP requests.

## Usage

### Create connection
A new connection can be created using the NewConnection function
```go
	hl := lra.HeaderList{"Content-Type": "application/json"}
	connection, err := lra.NewConnection(
		true,                            // use SSL
		"elasticsearch.example.com",     // server name or IP address
		9200,                            // port
		"",                              // no additional base endpoint
		"admin",                         // user name
		"1234",                          // password
		false,                           // we use a certificate generated by the elasticsearch CA
		"http://proxy.example.com:3128", // we use a proxy
		false,                           // it is not a socks5 proxy
		hl,                              // we want to pass those headers
		30*time.Second,                  // request timeout, 0 means lra.DefaultTimeout
	)
```
For a SOCKS5 proxy, pass `true` as the "socks" argument and the proxy address
either as `host:port` or as URL (`socks5://[user:password@]host:port`).

### Get a result
Getting a raw []byte:
```go
	statusRaw, err := connection.Get("/_cluster/health")
```

Getting parsed JSON:
```go
	var status map[string]any
	err := connection.GetJSON("/_cluster/health", &status)
```

### Contexts
Every function has a variant with the suffix `Context` which takes a
`context.Context` as first argument, allowing cancellation and per-request
deadlines:
```go
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	err := connection.GetJSONContext(ctx, "/_cluster/health", &status)
```

### Errors
If the server responds with a status code of 400 or above, the returned error
is a `*lra.StatusError` containing the status code and the response body:
```go
	if se, ok := errors.AsType[*lra.StatusError](err); ok && se.StatusCode == http.StatusNotFound {
		// handle 404
	}
```

### Other API functions
Currently the standard CRUD operations DELETE, GET, PUT, POST are implemented.
In addition, CONNECT, HEAD, OPTIONS, PATCH and TRACE are implemented but so far,
I didn't need them. So they have not been battle-tested.

For every type, there is a function returning the raw []byte data and a function
with the suffix JSON which parses the data into the value passed as last
argument (like `json.Unmarshal`). For HEAD requests, the response headers are
returned as JSON.
